Architecture proposal · packages/tokrec

One verdict, one loop, one abort

A redesign of the tokrec library around a single typed truth value, a pure tick policy, and a single cancellation scope. Breaking changes included and staged.

01Diagnosis

The library works. Its shape does not. Two of the three defects below are correctness bugs that survive only because the fixtures never exercise them; the rest are structural — every new source or output step costs edits in five files instead of one.

The common root: one value is doing three jobs. LiveInfo is simultaneously the verdict (is the room live?), the evidence (which of three page shapes told us?), and the transport result (here is the URL). Five modules each assemble it from their own partial view, so the mapping table is duplicated five times and each copy can drift.

02Target shape

Five bands. Arrows point one way. Only session holds mutable state; only adapters touch the network, the filesystem, or ffmpeg.

Today

LiveInfo is constructed in 22 places. The mapping reason → isLive is re-derived by decideTick, called from one place, tested in isolation from the real thing.

Proposed

Verdict is constructed by one total function. isLive and decideTick cease to exist; reason is the only axis and the compiler enforces exhaustiveness at the policy boundary.

03Domain — the truth value

Three decisions shrink the type surface. Drop isLive: it is a projection of reason. Drop the free-string source: it becomes an evidence trail. Split room from stream: a live room with no URL is a legitimate state, not a half-filled record.

domain/verdict.ts 
export type LiveReason =
  | "live"          // room live, stream URL resolved
  | "no-stream-url" // room live, no URL yet
  | "restricted"    // room gate refused (status_code 4003110)
  | "offline"       // room reported not live
  | "no-room-id"    // discovery exhausted, no room found
  | "error"         // transport/parse failure, no verdict reached

export interface RoomRef {
  readonly id: string
  readonly title: string | null
  readonly live: boolean
}

export interface StreamRef {
  readonly url: string
  readonly kind: "flv" | "hls"
}

export type SourceId = "page" | "api-live" | "profile" | "webcast"

export interface Evidence {
  readonly source: SourceId
  readonly outcome: "hit" | "miss" | "denied" | "error"
  readonly note?: string
}

export interface Verdict {
  readonly reason: LiveReason
  readonly room: RoomRef | null
  readonly stream: StreamRef | null
  readonly evidence: readonly Evidence[]
  readonly failure: TikTokError | null
}

reason is derived, never passed. This is the whole fix for the five-cascade duplication — every caller hands over facts, one function decides what they mean.

domain/verdict.ts 
export function verdictOf(x: {
  room?: RoomRef | null
  stream?: StreamRef | null
  denied?: boolean
  failure?: TikTokError | null
  evidence?: readonly Evidence[]
}): Verdict {
  const room = x.room ?? null
  const stream = x.stream ?? null
  const base = { room, stream, evidence: x.evidence ?? [], failure: x.failure ?? null }

  if (x.failure)        return { ...base, reason: "error" }
  if (!room)             return { ...base, reason: "no-room-id" }
  if (!room.live)        return { ...base, reason: "offline" }
  if (x.denied)          return { ...base, reason: "restricted" }
  if (stream)            return { ...base, reason: "live" }
  return { ...base, reason: "no-stream-url" }
}

Six branches replace 22 literals. Every reason value in the union is reachable and each is exercised by one line of this function, which is table-testable in ten lines.

04Discovery — a chain that cannot be killed by one throw

Today a source either returns a finished LiveInfo or null, and a throw ends the chain. Replace both with a four-case Candidate. Discovery now reports what happened; the orchestrator decides what it means.

adapters/tiktok/discovery/source.ts 
export type Candidate =
  | { kind: "room";   room: RoomRef; stream: StreamRef | null }
  | { kind: "denied"; room: RoomRef; code: number }
  | { kind: "miss";   note: string }
  | { kind: "failed"; error: TikTokError }

export interface DiscoveryContext {
  readonly user: string
  readonly log: Logger
  readonly page: PageReader     // read(user, "/live" | "") → { html, baseUrl } | null
  readonly webcast: WebcastReader // room(id) · alive(id)
  readonly signal: AbortSignal
}

export interface DiscoverySource {
  readonly id: SourceId
  find(ctx: DiscoveryContext): Promise<Candidate>
}
adapters/tiktok/discovery/chain.ts 
export async function discover(
  sources: readonly DiscoverySource[],
  ctx: DiscoveryContext,
): Promise<{ candidate: Candidate; evidence: Evidence[] }> {
  const evidence: Evidence[] = []
  let last: Candidate = { kind: "miss", note: "no sources configured" }

  for (const source of sources) {
    // A throw becomes evidence, never a dead end. This is tiktok.ts:154's bug, inverted.
    const candidate = await source.find(ctx).catch(
      (e): Candidate => ({ kind: "failed", error: toTikTokError(e) }),
    )
    evidence.push({ source: source.id, ...outcomeOf(candidate) })
    last = candidate
    if (candidate.kind === "room" || candidate.kind === "denied") break
  }

  return { candidate: last, evidence }
}

The sources shrink accordingly. page keeps its SIGI_STATE path but stops composing verdicts; it returns { kind: "room", room, stream } or { kind: "miss" }. api-live and profile lose their duplicated reason tables entirely. The 4003110 handling lives once, in the webcast adapter, as { ok: false, statusCode: 4003110 } — already true today, now with a single consumer.

WebcastReader exposes two methods instead of five. The generic escape hatch fetchFromRoomApi<T> disappears: each capability gets a named method that returns a domain type, so no caller can invent a fifth interpretation of room/info.

ports/tiktok.ts 
export interface WebcastReader {
  room(id: string, signal: AbortSignal): Promise<
    | { ok: true;  room: RoomRef | null }
    | { ok: false; statusCode: number }
  >
  alive(id: string, signal: AbortSignal): Promise<boolean>
}

export interface PageReader {
  read(user: string, path: "" | "/live", signal: AbortSignal): Promise<
    { html: string; baseUrl: string } | null
  >
}

Note signal on every port. Today cancellation stops at the tick boundary: an in-flight HTTP request during stop() runs to its 15-second timeout. With the signal passed through, stop() is immediate.

05Policy — a pure tick

The 100-line onTick mixes two things: what to do given a verdict (policy) and doing it (effects). Split them and the policy becomes a table.

policy/tick.ts 
export interface TickFacts {
  readonly recording: boolean
  readonly recordedSec: number
  readonly oneShot: boolean        // duration > 0
  readonly consecutiveErrors: number
  readonly stopRequested: boolean
}

export type TickPlan =
  | { kind: "poll";   note: string }
  | { kind: "hold";   reason: "restricted" | "no-stream-url"; room: RoomRef }
  | { kind: "record"; room: RoomRef; stream: StreamRef }
  | { kind: "stop";   why: "one-shot" | "user" | "gave-up" }

export function planTick(v: Verdict, f: TickFacts): TickPlan {
  if (f.stopRequested) return { kind: "stop", why: "user" }
  switch (v.reason) {
    case "live":
      return f.recording
        ? { kind: "poll", note: "already recording" }
        : { kind: "record", room: v.room!, stream: v.stream! }
    case "no-stream-url":
    case "restricted":
      return { kind: "hold", reason: v.reason, room: v.room! }
    case "offline":
      return f.oneShot && f.recordedSec > 0
        ? { kind: "stop", why: "one-shot" }
        : { kind: "poll", note: "offline" }
    case "no-room-id":
      return f.consecutiveErrors >= 10
        ? { kind: "stop", why: "gave-up" }
        : { kind: "poll", note: "no room" }
    case "error":
      return { kind: "poll", note: v.failure?.message ?? "error" }
  }
}

Two non-null assertions are the price of keeping room optional on Verdict. If that is unacceptable, make Verdict a discriminated union on reason and the assertions vanish — the cost is a wider type and more construction syntax. The policy file is where the choice is visible and reversible.

Why this matters more than it looks

Today the decision "is this tick live?" is spread across three if blocks in recorder/index.ts plus decideTick, and it branches on both reason and isLive — two fields that can disagree. With one axis, an impossible state cannot be constructed, and the CLI's display logic keys off the same value.

06Session & effects

RecorderSession owns the loop, the phase, and one AbortScope. Everything it calls takes the signal. Nothing else creates a controller.

session/abort.ts 
export interface AbortScope {
  readonly signal: AbortSignal
  close(reason?: string): void
}

export function abortScope(parent?: AbortSignal): AbortScope {
  const controller = new AbortController()
  if (parent) {
    if (parent.aborted) controller.abort(parent.reason)
    else parent.addEventListener("abort", () => controller.abort(parent.reason), { once: true })
  }
  return { signal: controller.signal, close: (r) => controller.abort(r) }
}
session/session.ts 
export interface RecorderDeps {
  readonly http: Http
  readonly media: Media
  readonly files: Files
  readonly clock: Clock
  readonly log: Logger
}

export function createRecorder(
  config: RecorderConfig,
  overrides: Partial<RecorderDeps> = {},
): RecorderController

// no, `let`, no `as`, no null checks: dependencies are built once, in start().
async function run(cfg: ResolvedConfig, deps: RecorderDeps, scope: AbortScope) {
  for (;;) {
    const { candidate, evidence } = await discover(sources, ctx)
    const verdict = toVerdict(candidate, evidence)
    emit("tick", { verdict })

    const plan = planTick(verdict, facts())
    if (plan.kind === "stop") break
    if (plan.kind === "record") await newJob(plan).finish()
    if (!(await sleep(cfg.intervalMs, scope.signal))) break
  }
}

RecordingJob replaces processRecording + pendingRemuxes. The job owns its in-flight ffmpeg work and exposes one method, so stop() no longer reaches into a shared array that a callee mutates.

session/job.ts 
export interface RecordingJob {
  readonly file: string
  // Awaits the in-flight download, then segment → convert → normalize. Idempotent.
  finish(): Promise<RecordedFile[]>
}

// Segmenting stops guessing filenames: ffmpeg reports its own list.
const args = [
  "-i", input, "-c", "copy", "-f", "segment",
  "-segment_time", String(seconds),
  "-segment_list", "pipe:1", "-segment_list_type", "csv",
  outputPattern,
]
// stdout lines: "file,start,end" — parse, don't re-read the directory.

Five direct node:fs imports become one Files port and one Media port. Two benefits beyond tidiness: post-processing tests stop needing a real temp directory, and the duplicate execa call in recorder/index.ts:76 (which re-implements ffmpeg-utils.ts) collapses into the port.

The old core/ tree disappears in one mechanical commit. Keeping the current layout "because it works" is what allowed types.ts to type itself from a factory's return value; the bands are the design, so they get to be directories.

Guardrail — a 40-line test, not a convention document

// packages/tokrec/test/architecture.test.ts
const ALLOWED: Record<Zone, Zone[]> = {
  domain:   ["domain"],
  policy:   ["domain", "policy"],
  ports:    [],
  adapters: ["domain", "ports", "lib"],
  session:  ["domain", "policy", "ports", "adapters", "lib"],
  lib:      ["lib"],
  root:     ["domain", "policy", "ports", "adapters", "session"],
}

// 1. every import edge respects ALLOWED
// 2. domain/ and policy/ import no node:* or bun:* module
// 3. no module in the graph is part of a cycle (DFS over resolved edges)
// 4. index.ts exports only from domain/, session/, lib/format, lib/utils

These four assertions are exactly the four failure modes seen today — cross-band imports, hidden I/O in policy, cycles, and a barrel that leaks internals. A reviewer no longer has to hold the graph in their head; the suite does. It also makes the next refactor cheap: the test tells you where a new file may live.

Version

Pre-1.0, so 0.14.0 with a BREAKING section is semver-legal. If the event and verdict shapes are meant to be a contract other people build on, take 1.0.0 now, while the only consumer is this repo's CLI — the cheapest possible moment to freeze a public surface.

What the CLI gains

  • bin.ts:181–256 — 14 subscriptions and two closures of display state (lastWasLive, firstOfflineTime) collapse to 3 handlers. The "offline repeat" timer can read Verdict.evidence instead of tracking its own history.
  • bin.ts:228 — the empty recording:end handler with its apologetic comment is deleted, not ported.
  • ui.ts unchanged: it already speaks in display.* verbs, which is the right seam.

10What this does not fix

Being explicit about scope, so this does not read as a promise of stability it cannot keep.

  • TikTok's page churn. Three extraction strategies remain because TikTok genuinely serves three shapes. The redesign makes adding a fourth a one-file change with a fixture test, not a guarantee that fixtures stay valid.
  • Live-network tests. All 95 tests run against captured fixtures. A redesign cannot fix the fact that the first sign of WAF drift is a production run — but the evidence trail on Verdict makes that run diagnosable from the log alone.
  • The peaknorm → @zfadhli/koko-cli transitive. Unchanged: picocolors and cli-spinners stay in the tree until that dependency is fixed upstream.
  • ffmpeg as a hard requirement. Kept. The Media port makes it swappable and testable, not optional.
  • Multi-room recording. Out of scope, but the shape permits it: RecorderSession takes a config and a scope, so N sessions behind a supervisor is an addition, not a rewrite. Today's god closure makes it a rewrite.
  • CHANGELOG for c322f20. Independent of this proposal; still owed.
Recommendation

Do PR A and PR B. A costs an afternoon and buys the guardrail; B removes the correctness bug at tiktok.ts:154 plus the duplication that will otherwise be copied a sixth time the next time TikTok changes its page. C and D are worth doing but are refactors of working code — schedule them behind whatever the recorder needs next, not before.
